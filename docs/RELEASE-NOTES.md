# v0.1.0-preview.4 — ADT endpoint and TLS management

[Türkçe](RELEASE-NOTES.tr.md)

This preview adds profile-scoped ADT connection and certificate management in Manager and the updated private ADT MCP. Explicit HTTP/HTTPS URLs, custom ports and proxy prefixes take precedence over legacy address lists. RFC system numbers do not determine web ports. Legacy blank URLs must be confirmed and saved before credentials are sent; opt-in address suggestions are unauthenticated and never prove ADT availability.

The ADT URL field includes “How do I find this address?” with a copyable Basis request, SMICM service guidance and the distinction between internal ICM and external Web Dispatcher addresses. EN/TR help is bundled and public. See [ADT/TLS guide](https://github.com/tamerinal/sap_mcp_windows/blob/v0.1.0-preview.4/docs/ADT-CONNECTIONS.md).

Profile certificates accept verified public PEM/DER files, show certificate identity/validity/SAN/SHA-256, and combine per-profile trust with Node defaults and Windows trust. No OS store or global TLS configuration is changed. Intermediate-only partial trust is disabled; hostname and dates remain checked. Unauthenticated server inspection grants no trust. TLS bypass is an explicit per-profile warning, off for new profiles. HTTP credentials have a persistent plaintext warning.

Manager tests the selected saved profile via a temporary private mapping without changing the shared active account. Actual MCP and Manager share the same Node transport. New diagnose_connection, inspect_tls_certificate and discover_adt_endpoints tools supplement existing tools. ping_system requires the full verification result. Stages cover configuration, effective DNS/TCP route, TLS, authentication, real ADT discovery and a read-only graph. Authentication rejection stops retries; redirects/cross-origin credential forwarding are blocked. Proxy environment/NO_PROXY are preserved; HTTPS CONNECT verifies origin TLS. Masked support export includes only approved metadata.

**Upgrade:** install the new Manager, use Install/repair selected MCP components to update ADT, then fully restart RFC/ADT MCP servers in Codex/Claude. Old ADT packages are deliberately blocked until connectionPolicyVersion=1 is installed. Existing settings schema, profiles, secret references and client registrations are preserved. CA references should be explicitly confirmed in Manager; do not copy another user's DPAPI secrets. RFC/PyRFC and runtime package hashes are unchanged; the RFC source repository is not modified. SDK is user-supplied and absent from both installers.

[Issue #4](https://github.com/tamerinal/sap_mcp_windows/issues/4) tracks delivery and pending acceptance. VALIDATION-SUMMARY.md lists actual source commits/CI/test outcomes. Tests use synthetic local HTTP/TLS servers and generated certificates, not live SAP. Private ADT source stays private; compiled JS and dependencies are extractable from public installers.

**Unsigned preview.** Clean Windows 10 22H2/11 including GUI-free/network-disabled installation, native accessibility/keyboard and live customer SAP acceptance remain pending. This builder has SAP GUI installed; tests do not invoke it. Inno Setup 6.7.3 reports non-commercial use only; appropriate licensing is required for commercial build/distribution. MIT does not override third-party terms. Existing previews are preserved.

Limitations: Basic/DPAPI account authentication; no new SSO/mTLS, interactive proxy authentication, OS trust editor, automatic OCSP/CRL/AIA retrieval or SAP-side certificate/service changes. Unresolved issuer-chain/root-trust conditions are reported honestly. Anonymous endpoints cannot prove the supplied account. Browser/Eclipse and Node trust stores differ. RFC SDK constraints, unsupported message-server/SNC/include modes, secret-bearing SAProuter and macOS limitations remain. This release does not claim every SAP environment works unconditionally.
